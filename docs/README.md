2. **[08 §十](08-部署与工程.md)** — 编码红线 48 条(每条都是"漏了会出数据错且不会立刻报错")。
3. **[09 §七·补](09-压测与验收.md)** — MVP 动工顺序 0–10 阶段,每阶段有可验证产出。

编码期间手边常备:**03 §十 字段对齐自检表**(每字段在 DDL/Redis/Lua/流程四栏都要有落点)+ **07 §3·补 错误码表**(写 controller 前先落 `Result<T>` + ObjectMapper `Long→String`)。

**阶段 0 必须在 `docker compose down -v` 后的干净环境跑一次**,并在那一次里验完四条地基(见 00 §6.5):① 起得来(首页不是 404、三库表齐、超管可登且行落在 `ds1`)② 四把密钥两两不等的启动断言真会拒绝启动 ③ **08 §7.2 三处时区一致** ④ **08 §7.3 `noeviction` + `appendfsync=everysec`**。后两条不验,所有时间判据与"库存放 Redis"的前提都建在错的地基上(配成 `allkeys-lru` 时 Redis 会静默删你的库存);前两条不验,换台机器就起不来而查不出原因 —— **`docker-entrypoint-initdb.d` 只在数据目录为空时执行,所以开发者的机器永远不是干净的**。

## 七条贯穿全局的纪律

1. **窗口期的终态意图只用 occupy 标记表达**(`cancelled`/`expired`);**occupy 的删除权只属于两处**:消费者落库成功、10.2a 回滚。
2. **幂等表写入时机的判据**:重复执行一次有唯一键/CAS 能变 no-op → **成功后写**;没有(界外调用)→ **动作前写**。
3. **任何"桶余量从 0 变正"的路径都必须 `DEL slot:full`**:10.2a / 10.3 / 增容,一个不能漏。
4. **每个 `NOT NULL` 列都要问"所有写入路径都拿什么填它"**;每个唯一键都要问"失败/重试路径会不会撞它连日志都写不下"(`qr_nonce` 就是反例)。
5. **每个跨边界传递的值都要问"到对面还是同一个值吗"**:JSON 边界(Long 超 `2^53` 被 JS 静默改写)、容器/驱动边界(时区默认 UTC 差 8h)、Redis 读法边界(通配扫描 vs 按 `bucket_count` 精确拼 key)。判据:**这一层的缺陷不会让功能测试变红**,必须靠"逐位比对真值"的用例专门抓(09 §6.7)。
6. **每个"承诺了资源隔离/容量保护"的句子都要指得出具体配置项**,否则是空承诺(与 `state_log` 曾经"有表无写入点"同构);**每个中间件的默认值都要问"对本项目是对的吗"**——Redis 默认无 `maxmemory`、`@Scheduled` 默认池 1、Docker `stop_grace_period` 默认 10s,三处默认值对本项目都是错的。判据:**这一层的缺陷连低并发压测都是绿的**,只在峰值/长跑/重启时显形(09 §6.8)。
7. **每个"从零起一次"的步骤都要有可执行定义**:假设接手者只有一台干净机器和这份文档,他能不能只靠文档把系统起起来?凡出现"初始化脚本/种子数据/超管账号/前端产物/topic 创建"却指不出具体文件与内容的,都是缺口。判据:**这一层的缺陷在功能测试里根本跑不到**——测试环境是手工搭好的,而缺口在"搭"这一步(09 §6.9)。另一半:**凡是"红线清单里有但代码里没断言"的条目,迟早会被违反** —— 动工时把 48 条红线过一遍,标出哪些能做成启动断言、哪些能做成集成测试。

> 缺陷分档与对应抓法见 **00 §6.3·补**:会变红 → 功能测试;永远绿 → 逐位比对真值;低并发也绿 → 峰值+长跑+主动杀进程;**根本跑不到 → `down -v` 后干净环境重起**(且这一档排在验收最前,起不来就什么都测不了)。
